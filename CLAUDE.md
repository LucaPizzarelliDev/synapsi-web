This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Next.js 16 — not the version you know

Next.js **16.4.5** + React **19.3**. APIs and conventions differ from older training data. Before non-trivial Next-specific work, check the local docs in `node_modules/next/dist/docs/` and heed deprecations (`AGENTS.md` is regenerated by `next dev` — commit it with your changes, don't fight it). Already relied on in `next.config.ts`:

- **`cacheComponents: true`** and **`partialPrefetching: true`** — be deliberate about dynamic vs. cached data.
- **Typed routes**: layouts/pages use generated globals `LayoutProps<"/path">` / `PageProps<"/path">` (e.g. `LayoutProps<"/portale">`), not hand-written prop types.
- Permanent redirect `/hermia → /viseria` (product rename 2026-10-24) — keep this pattern for future renames.

## Commands

Run these **inside `synapsi-web/`** (the workspace root `synapsi/` has no manifest): `cd synapsi-web`
first, or use `npm --prefix synapsi-web run <script>` for one-offs. Dependencies are **not**
installed by default — run `npm install` first, or `lint`/`tsc` fail with `command not found`.

```bash
npm install            # required once; node_modules is gitignored
npm run dev            # dev server (Turbopack) → http://localhost:3000
npm run build          # production build — the authoritative typecheck gate
npm run start          # serve the production build
npm run lint           # eslint flat config (next core-web-vitals + typescript)
npx tsc --noEmit       # typecheck — ONLY works after a build/dev has run
```

`tsc --noEmit` on a clean checkout fails with `Cannot find name 'LayoutProps'/'PageProps'`: those
are Next-generated route globals written to `.next/types/` (referenced by `tsconfig`). Run
`npm run build` (or `npm run dev`) first to generate them; `npm run build` is the real gate.

No test runner is configured — do not invent `npm test`. No Prettier/editorconfig — formatting follows ESLint and the surrounding code only.

## Architecture

One App Router app, no backend: a **public marketing site** and a **client-portal demo**, all Italian, all content from hardcoded TypeScript. There is no DB, API, auth, or data fetching.

### Routes — `src/app/`, two route groups
- **`(sito)/`** — public site. Layout `(sito)/layout.tsx` adds `Header`/`Footer`. One page per product (`viseria`, `prismia`, `chimeria`, `iridium`, `sport`) plus `metodo`, `studio`, `contatti`, and the homepage `(sito)/page.tsx`.
- **`portale/`** — client portal. `portale/accesso/` is a standalone login; everything else is under `portale/(area)/` wrapped by `PortalShell` (`src/components/portal/Shell.tsx`), marked `robots: noindex`. Sections mirror the products: `persone` (+ `[id]`), `manager`, `organizzazione`, `report` (+ `[id]`), `account`.
- Root `src/app/layout.tsx` sets fonts, `lang="it"`, and the skip-link. Every page exports its own `metadata`.

### Data layer — `src/lib/` (edit here first for any content change)
- **`site.ts`** — public-site + domain constants: `services`, `products`, `nav`, `contact`, the four evidence `codes` (OB/PS/AC/IP) + `codeBg`, `viseriaFactors`, `chimeriaCriteria` (Burke-Litwin order), `prismiaDimensions`, `methodSteps`, `team`.
- **`portal.ts`** — portal sample data + types: `Assessment`, `Report`, `prismiaCycles`, `checkups`, `activity`, `users`, `client`, `psychologists`, `stages`, and `formatDate`. Comments encode real product rules (e.g. Prismia consent gating) — preserve their meaning.

Pages render by mapping over these arrays; they don't fetch. Changing copy/figures = editing `src/lib`, not the JSX.

### Domain (needed to read the data)
Psychologist-led assessments with AI-assisted transcription/coding. Products read different levels: **Viseria** = a person in a role (Scouting Card) · **Prismia** = a manager via interview-based 360, consent-gated, development-only · **Chimeria** = the organization (12 Burke-Litwin areas) · **Iridium** = commercial networks. Four evidence codes — **OB** observable, **PS** pattern, **AC** competence, **IP** hypothesis — double as the brand palette.

## Conventions (match these before inventing new ones)

- **Exports**: pages → `export default` (Next requirement); components & `src/lib` helpers → **named exports**. See `src/components/ui.tsx`.
- **Server-first**: add `"use client"` only for interactivity. Today only `Header`, `ContactForm`, and portal `Shell`/`LoginForm`/`PeopleTable`/`ReportTable`/`PrintButton` are client. See `src/components/Header.tsx` for the client pattern (hooks + outside-click/escape).
- **Icons & graphics are inline SVG** — `src/components/portal/icons.tsx` (d-path registry) and `src/components/graphics.tsx`. No icon library, no emoji, no `next/image`/`<img>` anywhere.
- **Styling** is Tailwind v4 configured only in `src/app/globals.css` (`@theme` + `@utility`; no `tailwind.config`). Use the semantic tokens (`ink`, `paper`, `paper-2`, `body`, `line`, `primary`, `primary-soft`, and `ob`/`ps`/`ac`/`ip`) and custom utilities (`frame`, `display`, `marker`, `logotype`) — **never hardcode hex or ad-hoc colors**. Fluid type via `clamp()`. Fonts: `--font-display` (Schibsted), body Hanken, `--font-mono` (Spline).
- **Primitives first**: compose `Container`/`Section`/`Display`/`Button`/`Mark`/`CtaBand` from `src/components/ui.tsx` (and the portal equivalents in `src/components/portal/ui.tsx`) instead of re-implementing layout.
- **Accessibility is baseline, not optional** — the repo already does `aria-current`/`aria-expanded`/`aria-controls`, labelled nav landmarks, a skip-link, and `focus-visible` rings (`globals.css`). Keep that bar.
- **Italian everywhere**: copy, comments, route segments, data. Copy is concrete and plain ("fatti, non opinioni") — see `src/app/(sito)/page.tsx`.
- Import alias **`@/* → src/*`**.

## Design & code quality

This site has a strong, intentional "referto/codifica" visual language (ink hairline borders, mono section labels `§ NN —`, highlighter `marker`). The main failure mode here is generic AI-generated UI/code that breaks that language. Before writing UI, copy, or non-trivial code, follow:

## Verifying UI

Use the **`nuova-sezione`** skill when scaffolding pages/sections/components, and the
**`design-review`** skill to review UI against the rules above. For real (not just static)
verification, start the dev server (`npm run dev`) and let `design-review` drive the
**Playwright MCP** to open `http://localhost:3000`, screenshot pages, and check focus/contrast.
